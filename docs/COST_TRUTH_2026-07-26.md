## 2. Hosting 저장용량 20.45 GB의 정체

Hosting API 조회: 보관된 버전 **100개 이상**(nextPageToken 존재), 각 **85.1 MB / 336파일**.
조회된 첫 100개만 합쳐도 8.06 GB. 실제로 서빙되는 건 최신 1개뿐이고 나머지는 전부 배포 이력이다.

- 배포 1회 = +85 MB ≈ **월 +₩2**
- 무료 한도 10 GB → 현재 20.45 GB로 초과 상태(콘솔에 "한도 초과" 배지)

### 조치 (계정 설정 변경이라 사용자 승인 필요)
Firebase 콘솔 → Hosting → 버전 기록 관리에서 **보관 개수를 5~10개로 설정**.
20.45 GB → 약 0.9 GB(무료 한도 내)로 떨어져 **월 ₩491 → ₩0** 예상.

부수적으로 버전 1개가 85 MB인 것도 크다(아바타·재판방 PNG 에셋). 에셋 최적화는 별건.

## 6. 이번에 고친 것 — 방치된 탭의 백그라운드 읽기

Cloud Monitoring 5분 해상도로 새벽(무사용) 구간을 보니 규칙적인 버스트가 있었다.

```
01:15=89  02:15=3  03:15=3  04:15=88  05:15=2  06:15=88  07:15=3  08:20=87
```

**2시간 주기 ~88읽기 + 1시간 주기 ~3읽기.** 아무도 안 쓰는데 탭만 열려 있어서 나는 읽기다.

원인은 `setInterval` tick에 visibility/idle 가드가 없는 폴러들이었다.
`usePolling`은 이미 가드가 있었지만(숨김·무조작 시 skip), 개별 컴포넌트의 폴러는 빠져 있었다.

| 위치 | 주기 | 1회 읽기 |
|---|---|---|
| Dashboard `pollData` | 2시간 | jobs 47 + commonTasks 9 = **56** (CLASS2025 기준) |
| Dashboard `checkDateAndRefresh` | 1시간 | ~3 |
| VoteReminderBanner | 15분 | 법안 쿼리 + userVotes |
| NewBillPopup | 30분 | 위와 **동일한 쿼리**(전 페이지 상주라 모든 탭에 영향) |
| RealEstateRegistry 설정/매물 | 15분 | 매물 20~25 |

### 수정 (커밋 `1cfa391`)
`src/utils/backgroundPoll.js` 신설 — `usePolling`이 쓰던 규약을 헬퍼로 추출:
- tick은 `visibilityState === "visible" && !getIsIdle()`일 때만 실행
- 탭 복귀/조작 재개 시 마지막 조회가 `resumeGapMs`보다 오래됐으면 1회 즉시 조회

초기 1회 조회는 호출부가 그대로 직접 수행하므로 **첫 로드는 무영향**.
화면을 실제로 보는 순간엔 복귀 조회로 갱신되므로 **표시 신선도는 종전과 동일**.

라이브 검증: 대시보드 할일(직업+공통) 정상 렌더, 부동산 20건·설정값 정상, 콘솔 에러 0.
