## A. 버그 — 증거 있음

### A1. [높음] 주식 거래소 요약카드의 평가손익·수익률이 완전히 틀림
- 화면: 평가손익 **-13,225,353,657원**, 수익률 **-99.60%**
- 실제 보유: 삼성전자 136주(+152.76%), Amazon 1주(+2.87%), KB금융 111주(+40.23%) → **전부 수익, 합계 약 +2,598만원**
- 원인 `src/pages/banking/StockExchange.js:2046-2062`
  ```js
  portfolio.forEach((holding) => {
    totalInvested += holding.averagePrice * holding.quantity;   // ← 전 보유분(상장폐지 포함)
    if (!holding.delistedAt) {
      const stock = stocksMap.get(holding.stockId);
      if (stock && stock.isListed) totalValue += stock.price * holding.quantity;  // ← 상장 종목만
    }
  });
  ```
  원가는 **폐지·비상장분까지 전부** 더하고 평가액은 **상장분만** 더하는 비대칭 → 폐지 종목을 보유했던 계정은
  영구히 -99% 대 수익률로 표시됨. (실측 매수원가 132.8억 vs 화면 보유 3종목 실제 원가 2,733만원)
- 수정 방향: 폐지분을 (a) 원가에서도 제외하거나 (b) 폐지 시점 보상가로 평가액에 반영. 둘 중 하나로 통일.

## B. Firestore 읽기 — 실측치와 절감 포인트

### B1. [최대 절감 포인트] 오늘의 할일이 재방문마다 jobs+commonTasks를 다시 읽음
- `src/pages/dashboard/Dashboard.js`
  - `:888` 2시간 최소요청간격 가드가 `lastFetchTime` = **useRef** → 페이지를 떠났다 오면 리셋되어 가드가 사실상 무력
  - `:907` `if (!realtimeManager.current.listeners.has("jobs"))` — 실제 등록 키는 `:842`의 **`"polling"`** → 조건이 항상 참
  - → `setupPolling()`의 즉시 `pollData()`가 매 마운트 실행되어 `jobs`(limit 300) + `commonTasks`(limit 50)를 **무조건 getDocs**
  - 캐시(`dataCache`=globalCacheService, TTL 6시간)는 채워 넣기만 하고 **읽기 전에 신선도 검사를 하지 않음**
- 개선: `pollData()` 진입부에서 `dataCache.get(jobs_/commonTasks_)` 신선하면 네트워크 생략 + 가드 타임스탬프를
  컴포넌트 ref가 아니라 모듈 캐시에 저장. 학생 1명이 하루 5회 재진입한다고 보면 **학급 20명 기준 하루 약 6,900 reads 절감**
  (69 × 5 × 20 중 캐시로 대체 가능한 jobs/commonTasks 분).

### B2. 부팅 1회 156문서
- 학생 20명 × 하루 5회 접속 ≈ **15,600 reads/일**이 로그인 직후에만 발생. 부팅 경로(AuthContext classmates, 설정 문서군,
  ItemContext, 레이아웃 위젯)에서 세션 간 재사용 가능한 것부터 sessionStorage/globalCacheService로 옮기면 효과가 가장 큼.

### B3. 관리자 설정 진입 시 CF 8회
- 설정 화면 하나에서 Cloud Function을 8번 호출. 병합 가능한 호출이 있는지 점검 권장(비용·지연 모두 개선).

### B4. 페이지당 병렬 쿼리 수
- 경찰서 6개, 국회 5개의 `usePolling`이 각각 독립 쿼리. TTL 캐시가 있어 재방문은 저렴하지만 첫 진입 지연에 영향.

## C. UI/UX — 사용자 편의

### C1. [영향 큼] 화폐 단위·포맷이 페이지마다 다름
같은 잔액이 화면마다 다르게 보임:
- 헤더/국세청/나의 자산: `233억 5592만 7260알찬`
- 은행/주식/경매장/경찰서: `23,355,927,260원`
관리자 설정에 "화폐 단위(기본: 알찬)" 기능이 있는데 일부 페이지가 이를 무시하고 `원` + 콤마로 출력.
초등학생 대상 앱에서 단위 혼동은 실제 오해로 이어짐 → **공용 `formatCurrency` 하나로 통일 권장**.

### C2. 법안 벌금 금액이 포맷 없이 raw 출력
- 국회·대통령실 카드: `벌금: 1000000000원` (콤마·한글 단위 없음). 같은 목록의 다른 법안은 `1000만, 1억원`.

### C3. 죽은 UI가 그대로 노출
- 은행 탭 `🔒파킹 복구 (비활성)` — 눌러도 "비활성화되었습니다" 안내만 나옴(`ParkingAccount.js:1889`). 탭 자체를 숨기는 편이 나음.

### C4. 파괴적 버튼의 배치
- 오늘의 할일 헤더(교사 전용)에서 **"할일 리셋"(학급 전원 초기화)** 이 "새로고침" 바로 옆, 같은 크기.
  confirm 1회만 거치므로 오클릭 위험. 관리자 모달 안으로 옮기거나 2단계 확인 권장.

### C5. 폼 페이지의 공간 낭비
- 법원(고소장 제출), 경찰서(신고 제출)가 화면 좌측 절반만 사용하고 우측은 빈 공간.
  2단(폼 + 내 사건 현황) 구성이면 왕복 클릭이 줄어듦.

### C6. 부동산 배치도에 범례가 없음
- 노랑/분홍/파랑 색, 점선 테두리(내 소유), "판매중" 배지의 의미를 설명하는 범례 없음.
- 상단 통계(전체 30 / 개인소유 12 / 임대중 20 / 판매중 13)도 합이 맞지 않아 보임 — 중복 카운트라면 각주 필요.

### C7. 나의 자산 정보 우선순위
- 가장 중요한 **총 순자산·파킹통장·보유 쿠폰 카드가 화면 최하단**(스크롤해야 보임).
- 상단 "보유 현금" 카드는 좌측 2/3가 빈 공간.

### C8. 라벨 불일치
- 사이드바 "대통령실" ↔ 페이지 제목 "정부 조직도". 조직도보다 법안 목록이 먼저 나와 정보 구조도 혼란.

### C9. 색 대비
- 아이템 카드의 노란 "선물하기" 버튼(흰 글자) 대비 낮음. 아바타 상점 "착용 중" 헤더 텍스트도 거의 안 보임.

### C10. 목록 UI
- 학습 게시판 표: 날짜 열이 두 줄로 깨지고, 글이 늘어나도 페이지네이션이 없음.
