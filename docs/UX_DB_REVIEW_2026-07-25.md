- 교훈: `overflow-hidden` + 고정 `max-h` 조합은 항목이 늘어나면 조용히 잘린다.
  **가시성 점검에 `getBoundingClientRect()`만 쓰면 클리핑을 못 잡는다** — 조상의 `scrollHeight` vs `clientHeight`를 함께 봐야 한다.

### B1. [최대 절감 포인트] 오늘의 할일이 재방문마다 jobs+commonTasks를 다시 읽음
- `src/pages/dashboard/Dashboard.js`
  - `:888` 2시간 최소요청간격 가드가 `lastFetchTime` = **useRef** → 페이지를 떠났다 오면 리셋되어 가드가 사실상 무력
  - `:907` `if (!realtimeManager.current.listeners.has("jobs"))` — 실제 등록 키는 `:842`의 **`"polling"`** → 조건이 항상 참
  - → `setupPolling()`의 즉시 `pollData()`가 매 마운트 실행되어 `jobs`(limit 300) + `commonTasks`(limit 50)를 **무조건 getDocs**
  - 캐시(`dataCache`=globalCacheService, TTL 6시간)는 채워 넣기만 하고 **읽기 전에 신선도 검사를 하지 않음**
- 개선: `pollData()` 진입부에서 `dataCache.get(jobs_/commonTasks_)` 신선하면 네트워크 생략 + 가드 타임스탬프를
  컴포넌트 ref가 아니라 모듈 캐시에 저장. 학생 1명이 하루 5회 재진입한다고 보면 **학급 20명 기준 하루 약 6,900 reads 절감**
  (69 × 5 × 20 중 캐시로 대체 가능한 jobs/commonTasks 분).

### B2. 부팅 1회 156문서
- 학생 20명 × 하루 5회 접속 ≈ **15,600 reads/일**이 로그인 직후에만 발생. 부팅 경로(AuthContext classmates, 설정 문서군,
  ItemContext, 레이아웃 위젯)에서 세션 간 재사용 가능한 것부터 sessionStorage/globalCacheService로 옮기면 효과가 가장 큼.

### B3. 관리자 설정 진입 시 CF 8회
- 설정 화면 하나에서 Cloud Function을 8번 호출. 병합 가능한 호출이 있는지 점검 권장(비용·지연 모두 개선).

### B4. 페이지당 병렬 쿼리 수

### C1. [영향 큼] 화폐 단위·포맷이 페이지마다 다름 — ✅ 수정 (커밋 `ab90707`)

- 폼 라벨의 `(원)`, placeholder 예시, alert/confirm 문구, 활동 로그 문구까지 포함
- 서술형 "만원"은 "만 {단위}"로 (예: `200만 알찬`)
- 업적(`achievementSystem`)은 모듈 상수라 **getter로 지연 평가** — 로드 시점 단위 고정 방지

- 국회·대통령실 카드: `벌금: 1000000000원` (콤마·한글 단위 없음). 같은 목록의 다른 법안은 `1000만, 1억원`.

### C3. 죽은 UI가 그대로 노출
- 은행 탭 `🔒파킹 복구 (비활성)` — 눌러도 "비활성화되었습니다" 안내만 나옴(`ParkingAccount.js:1889`). 탭 자체를 숨기는 편이 나음.

### C4. 파괴적 버튼의 배치 — ✅ 수정
- 오늘의 할일 헤더(교사 전용)에서 **"할일 리셋"(학급 전원 초기화)** 이 "새로고침" 바로 옆, 같은 크기.
  confirm 1회만 거치므로 오클릭 위험.
- 조치: 구분선으로 시각 분리 + **학급 코드를 직접 입력해야 실행**되는 2단계 확인 추가.

### C5. 폼 페이지의 공간 낭비 — ✅ 개선
- 법원(고소장 제출), 경찰서(신고 제출)가 화면 좌측 절반만 사용하고 우측은 빈 공간.
- 원인은 `max-width: 600px`만 있고 가운데 정렬이 없었던 것. 720px + `margin: auto`로 조정.
  (2단 구성은 정보 구조를 바꾸는 큰 변경이라 이번엔 보류)

### C6. 부동산 통계 합 불일치 — ✅ 개선 (범례 지적은 오보)
- ~~범례 없음~~ → **오보**. 범례는 배치도 바로 아래(`layout-legend`)에 원래 있었다(스크롤 밖이라 못 봄).
- 상단 통계(전체 30 / 개인소유 12 / 임대중 20 / 판매중 13)는 **중복 집계가 맞다**
  (한 부동산이 개인 소유이면서 임대 중이고 판매 중일 수 있음) — 코드 확인 완료, 버그 아님.
- 조치: "중복 집계됩니다" 각주 추가. 다만 '전체'만 `settings.totalProperties`, 나머지는 `properties` 기준이라
  둘이 어긋나면 부분합이 전체를 넘을 수 있다(잔여 리스크로 기록).

### C7. 나의 자산 정보 우선순위 — ✅ 수정
- 가장 중요한 **총 순자산·파킹통장·보유 쿠폰 카드가 화면 최하단**(스크롤해야 보임).
- 조치: 3장 카드를 '최근 입출금 내역' **위**로 이동. 보유 현금 카드의 여백은 의도된 강조 레이아웃이라 유지.

### C8. 라벨 불일치 — ✅ 수정
- 사이드바 "대통령실" ↔ 페이지 제목 "정부 조직도" → 제목을 "대통령실"로 통일.
- 조직도보다 법안 목록이 먼저 나오는 정보 구조는 그대로 둠(기능 재배치라 별건).

### C9. 색 대비 — ✅ 수정
- 아이템 카드 "선물하기"(amber-500 + 흰 글자) 대비 **2.1:1**, "국고 되팔기"(sky-500 + 흰 글자) **2.5:1**
  — WCAG AA(4.5:1) 미달. 각각 amber-700/sky-700으로 내려 **5.0:1 / 5.9:1** 확보, 비활성 상태 글자색도 진하게.
- 아바타 상점 "착용 중" 헤더는 `text-slate-700` on 밝은 배경이라 실제로는 문제없음(오보).

### C10. 목록 UI — ✅ 수정 (페이지네이션 지적은 오보)
- 날짜가 `toLocaleString` 전체 형식("2026. 07. 25. 오후 07:49")이라 160px 열에서 두 줄로 깨짐
  → 목록 전용 짧은 형식(`07.25 19:49`, 작년 이전은 `25.07.25`) + `white-space: nowrap`, 전체 날짜는 title 툴팁.
- ~~페이지네이션 없음~~ → **오보**. `startIdx` 기반 페이지네이션이 이미 구현돼 있다.

## D. 확인 필요

0. **(해소됨) 계정 구분** — 위 A~C의 1차 관측은 앱 관리자 계정(CLASS2025, 학생 0명)에서 수행했고,
   이후 실사용 학급(BG6QUC, 교사 iw-lab, 학생 21명)에서 재검증했다. 학급별 실측 차이:
   - 오늘의 할일 재진입: CLASS2025 69문서 / BG6QUC 54문서 → **수정 후 3문서**
   - 나의 자산 첫 진입 118~133문서(실데이터), 재진입 6문서
   - 주식 첫 진입 361문서 / 재진입 11~12문서(배치 로더 캐시 정상)
   - 경찰서 첫 진입 149~394문서(usePolling 6종 동시)
   - A1(주식 수익률 붕괴)은 폐지 종목 보유 계정에서만 발현 → BG6QUC에선 미발현
   - A4(경매 정산 실패)는 CLASS2025 레거시 데이터 전용 → BG6QUC 경매장 정상("진행 중인 경매가 없습니다")

1. **CLASS2025에 학생 0명** — 학생 목록·권한 위임·돈 보내기 모두 "학생 없음"으로 표시됨.
